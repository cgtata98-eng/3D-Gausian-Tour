3DRoomTour — デザイン方向性の比較

4 カラムはすべてまったく同じ HTML マークアップで、差分は CSS 変数の値だけです。 つまりここで見えている違いが、そのまま src/ui/design-tokens.ts の変更差分にあたります。 「現行」列は design-tokens.ts と components/Pill.tsx の実値をそのまま転記しています。

「PC だからガラス感が出ないのでは？」— レンダリングの制約ではありません。 Windows の Chromium は backdrop-filter を完全にサポートしています。効きが弱く見える理由は 3 つで、うち 2 つは PC 固有です。 ① 背景に情報がない（B 列の背景スイッチで確認できます）。 ② DPR が 1x — iPhone は 3x なので 1px の縁が物理 3 ピクセルで描かれてクッキリ出ますが、1x モニタでは文字どおり 1 ピクセルなので消し飛びます。今回 B の縁を 1.6px に上げたのはこの対策です。 ③ 画面に対する要素の比率 — iPhone は幅 390pt にボタンが 120pt 占めますが、27 インチでは同じボタンが画面の数 % しかなく、光学効果が視認サイズを下回ります。 下の「スマートフォン UI」セクションが、本来の見え方です。

  • トラックの内側余白 — 参照はコントロール高の約 28% が余白。前回の 6px から 13px（この場では 16px）へ。ここが最大のズレでした。

  • 輪郭 — 完全な無ではなく、白い面のさらに外側にごく薄い灰の 1px リング（0 0 0 1px rgba(148,154,172,.10)）。無いと背景に溶け、濃いと「線で描いた UI」になります。

性能 backdrop-filter は数箇所 オーバーレイのみ。3D の上に数枚 要注意。ボタン 1 個ずつが backdrop-filter を持つ。ビューア上は枚数を絞る前提 ゼロコスト。blur を一切使わない。3D の上に何十個置いても FPS に影響しない
1x モニタでの再現性 — 良好（面で見せるので細線に依存しない） 縁を 1.6px に上げて対策済み。それでも Retina には劣る 最も安定。光の広がりで見せるので DPR に一切依存しない
作業範囲 — トークンの CSS 変数化 + ダークセット + viewer スコープ適用 トークン差し替え + 縁／鏡面用の擬似要素を各プリミティブに追加 + canvas の背景設計 トークン差し替え + 擬似要素は不要（box-shadow だけで完結）+ 余白とフォントサイズの一段拡大
